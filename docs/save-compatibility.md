# 存档兼容

项目 JSON 继续使用 `format_version: 1`，新增字段带默认值。0.3 新存档使用 `version: 2`，旧存档使用 `version: 1`；两者由 0.3 播放器读取。

## 可以继续读取的修改

- 修改对白、标题、选择显示文字、图片、音轨、表情、舞台布局与项目主题。
- 调整图布局、章节、作者信息、创作待办。
- 新增不影响已记录节点控制流程的后续内容。
- 使用节点标识“更新”改名，系统会记录旧标识到新标识的迁移，并更新现有引用。
- 新增布尔变量：读取时为当前状态和每一步回退历史补齐项目默认值；已有变量保留存档值。

## 需要明确处理的修改

存档保留当前节点与最多 500 步历史的节点类型、实际跳转、选择顺序、条件和赋值。修改这些节点的控制流程，或删除存档使用的变量时，读取会说明原因并拒绝直接套用。选择顺序不能随意重排。

节点替代可在“项目设置 → 存档兼容与节点迁移”填写旧标识和新目标。迁移会检查循环、目标存在性和控制流程；不会绕过检查强行读取。要彻底重写故事，可创建“独立副本”，由新作品标识使用独立存档。

检查覆盖的是存档保留的节点结构与变量形状，并不能判断自然语言故事语义，也不是防篡改机制。最近 500 步以前的剧情不在新存档的兼容清单中。

## 读取 0.2 存档

0.2 存档只有完整内容指纹，无法从存档本身恢复当时的节点结构。因此：

1. 首次在 0.3 打开不含 `save_compatibility` 的旧项目时，会在内存自动记录该版本基线；正式保存项目后基线持久保留。
2. 如果玩家使用更早版本的存档，在项目设置导入**当时原始的项目 JSON**作为兼容基线，不会覆盖当前故事。项目标识必须相同，最多 16 个基线。
3. 读取时先确认指纹对应的基线，再检查最近经过节点与当前结构。缺少基线时不会猜测迁移。

测试中的 `tests/fixtures/v0.2-save.json` 由 v0.2.0 标签的模型与运行代码实际生成，固定指纹用于防止兼容实现自证正确。

新版读取后再次保存会写入版本 2。0.2 程序不能读取新格式。发布更新时请同时更新 `Game.exe`，保留原作品 ID 与必要基线。旧数据目录继续读取；独立副本会建立新的作品 ID。
